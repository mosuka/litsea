# 予測パイプライン

本章では、`Segmenter::segment()` が入力テキストを処理する手順をステップごとに解説します。

## 例: "これはテストです。" の分割

### ステップ 1: パディングで配列を初期化

```text
chars: ["B3", "B2", "B1"]
types: ["O",  "O",  "O" ]
tags:  ["U",  "U",  "U", "U"]
```

tags 配列には "U" が 1 つ余分に追加されます。これは `tags[3]` が最初の実際の文字のタグを表し、先行する境界判定がないため "Unknown" に設定されるためです。

### ステップ 2: 入力文字のスキャン

入力の各文字について、言語固有のパターンを使用して種別を決定し、配列に追加します:

```text
chars: ["B3","B2","B1", "こ","れ","は","テ","ス","ト","で","す","。"]
types: ["O", "O", "O",  "I", "I", "I", "K", "K", "K", "I", "I", "P"]
```

### ステップ 3: 終了センチネルの追加

```text
chars: [..., "。", "E1", "E2", "E3"]
types: [..., "P",  "O",  "O",  "O" ]
```

### ステップ 4: 反復と予測

位置 `i` を 4 から `len(chars) - 3` まで繰り返します:

```text
i=4 (れ): Extract features → predict → label=-1 (O) → word="これ"
i=5 (は): Extract features → predict → label=+1 (B) → push "これ", word="は"
i=6 (テ): Extract features → predict → label=+1 (B) → push "は", word="テ"
i=7 (ス): Extract features → predict → label=-1 (O) → word="テス"
i=8 (ト): Extract features → predict → label=-1 (O) → word="テスト"
i=9 (で): Extract features → predict → label=+1 (B) → push "テスト", word="で"
i=10(す): Extract features → predict → label=-1 (O) → word="です"
i=11(。): Extract features → predict → label=+1 (B) → push "です", word="。"
```

### ステップ 5: 最後の単語をプッシュ

残りの単語 "。" を結果に追加します。

### 結果

```text
["これ", "は", "テスト", "です", "。"]
```

## 各位置での予測の仕組み

`segment()` は特徴量文字列を一切構築しません。モデルのロード時に、セグメンタは
学習器の文字列キー付き重みを **packed `u64` 特徴キー**に一度だけコンパイルし
（後述）、ホットループは整数のみで動作します。各位置 *i* で、セグメンタは以下を
実行します:

1. **特徴量のインデックス化** -- 38--42 個のテンプレートそれぞれについて、関連する
   境界タグ ID・文字種 ID・文字コードポイントから整数キーをスタック上で導出する。
   タグ/文字種のみのテンプレート（42 中 29 個）は小さな mixed-radix インデックスを
   計算し、文字を含むテンプレート（`UW*`, `BW*`, `WC*`）は `u64` キーにパックする
   （テンプレート ID が最上位バイト、タグ/種別は 8 ビット、文字は 24 ビット。
   パディングセンチネル `B3`...`E3` は Unicode スカラー範囲の直上のコードにマップ）。
   アロケーションも文字列整形も発生せず、dense テンプレートではハッシュ計算も
   発生しない
2. **スコアの計算** -- タグ/文字種のみのテンプレートは、テンプレートごとの密配列から
   mixed-radix インデックスで重みをロードする（単一の配列ロード）。文字を含む
   テンプレートは `FxHashMap<u64, f64>` を検索する。どちらの場合も未知の特徴量は
   0.0 を加算し、バイアスから始まる累積スコアに足し込む。バイアス自体は
   キャッシュされたフィールド（`-sum(model) / 2.0`、重みを変更するすべての経路で
   同期される）であり、文ごとに 1 回読み取られるだけで、位置ごとに再計算されることは
   ない:

   ```text
   score = bias + sum(weight(template, context) for each template)
   ```

3. **判定** -- `score >= 0` の場合、その文字は新しい単語を開始（境界）、そうでなければ現在の単語を継続
4. **タグの更新** -- tags 配列に B または O のタグ ID をプッシュし、後続の位置での特徴量抽出に影響を与える

packed コンテキスト（`packed_context`）は、単語組み立て用の文字列スライスを入力から
直接借用し、並行して `u32` 文字コード配列と `u8` 文字種 ID 配列を保持します。
センチネルエントリ（`B3`...`E3`）は静的な値です。

### Packed スコアリングテーブル

特徴テンプレートは宣言的なテーブル（`packed_model::TEMPLATES`）として一度だけ
定義され、そこから 3 つの消費者が導出されます: 学習・抽出・POS パスで使用される
文字列ライター、`segment()` が使用する整数キーライター、そしてモデルの各特徴量
文字列を整数キーへ変換するロード時パーサです。コンパイルは
`Segmenter::with_learner` で先行して行われ、学習器が変更されると
（`learner_mut()` / `add_corpus`）無効化され、次の `segment()` 呼び出しで遅延
再構築されます。

コンパイル済みモデルは、キー空間のサイズで使い分ける 2 つのルックアップ構造の
ハイブリッドです。タグ/文字種のみの 29 テンプレート（`UP*`, `BP*`, `UC*`, `BC*`,
`TC*`, `UQ*`, `BQ*`, `TQ*`）はドメインが極小（境界タグ 3 種、文字種コード
8--10 種/言語）なので、mixed-radix 積の厳密サイズで確保した**直接インデックスの
密配列**（日本語で合計約 74KB）を持ち、スコアリングはハッシュ計算なしの単一の
配列ロードになります。文字を含む 13 テンプレート（`UW*`, `BW*`, `WC*`）は
21 ビットのコードポイントを含むため、重みは packed キーで検索する
`FxHashMap<u64, f64>` に残ります。

セグメンタの言語では生成し得ないモデル特徴量（例: 日本語セグメンタにおける
韓国語の文字種コード）は両構造から除外されます。それらはスコアリング時に
到達不能なので、スコアには影響しません。マップの検索ミスは `0.0` を加算し、
密配列の未設定エントリは `0.0` を保持するため、浮動小数点の累積順序 --
したがって分割出力 -- は従来の文字列キー実装とビット単位で一致します。

## 単語分割と品詞タグ付けの同時実行（`segment_with_pos`）

`segment_with_pos` は、AdaBoost の代わりに Averaged Perceptron を使用して同じ左から右へのパイプラインを実行します:

1. 各位置の特徴量は再利用可能な `Vec<String>`（`collect_attributes`）に収集され、パーセプトロンのクラス別スコアベクタも再利用可能なバッファです。
2. パーセプトロンは、特徴量ごとに 1 回の `FxHashMap` 検索（特徴量 → クラス別重みベクタというレイアウト）で、各位置の `SegmentLabel`（`B-<POS>` または `O`）を予測します。
3. **最初の文字位置**での予測が最初の単語の品詞を決定します。#100 以降、POS 学習パイプラインもこの位置を出力するため、学習と推論は対称になります（境界（AdaBoost）パイプラインは、最初の位置のラベルが自明であるため、依然としてこの位置をスキップします）。
4. `B-<POS>` ラベルは現在の単語を確定させ、その品詞を持つ新しい単語を開始します。`O` は現在の単語を延長します。

## 学習と予測の比較

| 観点 | 学習（`process_corpus`） | 予測（`segment`） |
|------|---------------------------|----------------------|
| タグの情報源 | アノテーション済みコーパスから事前計算 | モデルにより動的に生成 |
| 最初のタグ | "U"（位置 3 の "B" を上書き） | "U"（先行する判定なし） |
| 最初の位置 | 境界パイプラインはスキップ、POS パイプラインは出力する（#100） | POS モードは最初の単語の品詞を予測するためにこの位置を予測する |
| ラベル | コーパスから既知（+1 または -1） | AdaBoost による予測 |
| 特徴量 | コールバックを通じてファイルに書き出し（文字列形式） | packed `u64` キー、文字列なし |

学習時は、タグが正解のコーパス分割から導出されるため、モデルは正しい境界判定から学習します。予測時は、タグがその場で生成されるため、各判定は過去のすべての予測に依存します -- これは**左から右への貪欲法**（Left-to-right Greedy）アプローチです。

## パフォーマンス特性

分割アルゴリズムは入力長に対して**線形**です:

- 各文字位置を 1 回ずつ訪問: O(n)
- 各位置での特徴量抽出: O(1)（固定数のテンプレートを、それぞれスタック上の `u64` にパック）
- 各位置での予測: O(f)、f はアクティブな特徴量の数（約 38-42）。タグ/文字種のみの 29 テンプレートは密配列の直接ロード、文字を含む 13 テンプレートは 1 回の整数キー `FxHashMap` 検索
- 合計: O(n * f)、実質的に O(n)
- アロケーションの特性: packed コンテキストは単語スライスを入力から借用し、フラットな `u32`/`u8` 配列を保持する。バイアスはキャッシュされ、ホットループ内では文字列を一切構築しない（packed テーブル自体はモデルロードごとに 1 回、ホットパス外でコンパイルされる）
