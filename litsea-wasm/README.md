# litsea-wasm

WebAssembly binding for [Litsea](https://github.com/mosuka/litsea), a compact word segmentation and POS (Part-of-Speech) tagging library for Japanese, Chinese, Korean, and English. Runs in browsers, Deno, and bundlers.

[日本語のREADME](README_ja.md)

For Node.js, use [`litsea`](../litsea-nodejs/README.md) instead — the native binding is faster and can also train models.

## Installation

```sh
npm install litsea-wasm
```

The module is 178 KB (82 KB gzipped); models are downloaded separately.

## Usage

```js
import init, { Segmenter } from 'litsea-wasm'

await init()

// The page fetches the model and passes the bytes.
const bytes = new Uint8Array(await (await fetch('/models/japanese.model')).arrayBuffer())
const seg = Segmenter.fromBytes('japanese', bytes)

seg.segment('これはテストです。')
// [ 'これ', 'は', 'テスト', 'です', '。' ]

seg.free()   // WebAssembly objects are not garbage collected
```

There is **no `fromUri`**: reqwest's wasm backend cannot build with the timeouts Litsea sets, and having the page fetch the model is the better shape anyway — caching, CORS, progress, and retries stay where the application can control them.

The language name and its ISO 639-1 code are interchangeable (`'ja'`, `'japanese'`).

### POS tagging

```js
const posBytes = new Uint8Array(await (await fetch('/models/japanese_pos.model')).arrayBuffer())
const seg = Segmenter.fromBytes('japanese', posBytes)

seg.segmentWithPos('これはテストです。')
// [ Token { surface: 'これ', pos: 'PRON', start: 0, end: 6 }, ... ]
```

`start` and `end` are **byte** offsets into the UTF-8 encoding. JavaScript string indices are UTF-16 code units, so slice with `TextEncoder` / `TextDecoder`:

```js
const bytes = new TextEncoder().encode(text)
new TextDecoder().decode(bytes.subarray(token.start, token.end))   // === token.surface
```

Calling `segmentWithPos` on a segmentation-only model throws an error with `code === 'pos_unavailable'`. The model file identifies its own kind, so `hasPos` reports what was loaded.

### Caching models

Models are 84 KB – 8 MB and cross the network once per visitor. The package ships an optional helper that keeps them in Cache Storage:

```js
import { fetchModel, clearModelCache } from 'litsea-wasm/js/cache.js'

const bytes = await fetchModel('/models/japanese.model')   // cached after the first visit
```

It falls back to a plain fetch when Cache Storage is unavailable (an insecure context), so callers do not need to branch.

## Memory

`Segmenter` holds the compiled model — several megabytes for a POS model — and WebAssembly objects are **not** garbage collected. Call `free()` when a segmenter is no longer needed.

## What this binding does not do

| | Why |
|---|---|
| No `fromUri` | reqwest's wasm backend cannot build with Litsea's timeouts; fetch in JS instead |
| No training | `Extractor` and the trainers are path-based, and wasm32 has no filesystem — tracked as a follow-up for in-memory APIs in `litsea` |
| No `CancelToken` | With no training there is nothing to cancel |

## Errors

Every error carries a `code`, matching the Node.js binding:

| `err.code` | Raised when |
|-----------|-------------|
| `invalid_argument` | Unknown language name |
| `model` | The file is a legacy joint POS model |
| `parse` | The model is malformed or not UTF-8 |
| `pos_unavailable` | POS tagging requested from a segmentation-only model |

## Development

```sh
make test-litsea-wasm    # cargo test + wasm-pack test --headless
make build-litsea-wasm   # wasm-pack build --target web
```

The browser tests compare against fixtures generated by the `litsea` CLI (`tests/generate_fixtures.sh`), so the reference implementation decides what is correct.

If `wasm-pack test` reports every test passing and then fails with `PermissionDenied`, the geckodriver on `PATH` is snap-confined; the tests themselves ran. Install a non-snap geckodriver, or run with `--chrome`.
